# Architecture

The system is split into a public customer portal and a protected admin panel, sharing one REST API and one MySQL database.

```
QR / Website
    → React customer form (/enquiry)
        → POST /api/v1/enquiries
            → Express validation (Zod)
            → Sequelize transaction
                → find/create customer (by mobile)
                → unique enquiry number ENQ-YYYY-NNNNNN
                → enquiry + status history
            → PDF acknowledgement (outside critical path if it fails after commit)
            → WhatsApp send (never inside the DB transaction)
            → success page
```

Admin users authenticate with JWT. Authorization is enforced in Express middleware by role:

| Role | Access |
|---|---|
| SUPER_ADMIN | Full access including users, audit logs, settings |
| ADMIN | Dashboard, customers, enquiries, follow-ups, reports, WhatsApp, assign |
| STAFF | Assigned enquiries, remarks, permitted statuses, follow-ups |

Layers: `routes → controllers → services → models → MySQL`.

WhatsApp lives in `backend/src/integrations/whatsapp`. Controllers never call a vendor SDK directly. Default provider is `mock`. Set `WHATSAPP_PROVIDER=http` plus API credentials for a live Cloud API-compatible endpoint.

PDF acknowledgements are generated by PDFKit under `backend/storage/confirmations`. They are enquiry confirmations, not payment receipts.
